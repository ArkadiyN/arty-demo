## Patterns

- **Most B rows cost very little.** 9 of the 12 were folded into a cycle that a real finding had already forced, or were one-line prose or limitation fixes. The expensive multi-cycle work (lethal axis ×2, familyA z_rep, target-height quadrature ×2) all fell in A or C. A materiality gate would have saved roughly one investigation per file, not whole fix cycles. The one real waste was repetition: in lethal-fragment-density-field pass 2 the modeler re-argued the same false invariance claim instead of dropping it. A tolerance does nothing about that.
- **What separated C from B before the outcome was known:** a C finding named a *cause that is not local to the number that exposed it*. Examples: an interleaved-column misread (one row, but the mechanism covers the whole table), a bound quoted at the default δ while the slider allows 2×, an axis convention that differs off the x=0 plane, a P_k-given-hit→1 choice presented as a citation, and a kernel evaluated on its own gate root. In each case the reviewer could point to *another config or consumer where the same cause bites*. In a B finding the reviewer had already bounded the effect with a computed margin: P_k saturates, the fail is by 4 decades, the V0 bound of 1.29× sits against a 7–33× gap, the oracle error is 5e-7. "Can you name where else this cause applies?" plus "is there a computed margin?" sorted every row correctly in hindsight.
- **A tolerance gate is only safe on an output delta that was actually computed across the whole exposed parameter range.** Gated on the raw signature (a 1e-16 residual, one table row, a ≤3.5% bound at the default δ), it would have wrongly filtered 3 of the 5 C rows. Gated on "the code is unchanged, so delta = 0" (justification-only findings), it would have filtered the lethal axis non-equivalence, which was the same x-mirror bug later confirmed to ship N=0 at live test points in legacy-field-shell-axis-fix.
- **Verdict-meaning findings have zero numeric delta and can be decision-critical.** Example: the Family A PASS against the 1944 card is two offsetting errors, one of them a threshold ~10× stricter than the card's. A numeric tolerance cannot represent this. The gate needs a separate "does this change what the verdict means?" question.
- **Executed checks were the discriminator, and they cut both ways.** The costliest cycle (familyA) came from a derivation whose magnitudes were "not executed". Dense sweeps turned "looks small" into either A/C or a proven-zero B. Running the real code also *prevented* a false finding (breakup-velocity power-counting). A scoping-time tolerance only pays off if review routinely produces a computed delta to compare against it.
