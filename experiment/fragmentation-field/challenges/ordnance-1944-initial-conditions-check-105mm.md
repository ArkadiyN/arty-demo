# 105mm M1 HE — initial-condition check against ordnance-1944.md

Investigation only (no `src/arty/` changes). Repeats the 75mm M48 check
(`ordnance-1944-initial-conditions-check-75mm.md`) for the 105mm M1 HE shell,
to see whether the same pattern (V0 mismatch direction, threshold match, and
especially the drag/retardation-coefficient gap) holds here too.

## Source-stated values (`doc-reference/wound-ballistics/ordnance-dept-1944-shell-fragment-damage/ordnance-1944.md`)

- (a) Initial fragment velocity (V0): **3,500 f/s** (= 1,066.8 m/s), stated
    explicitly as a header line directly above Table 51/52
    ("INITIAL FRAGMENT VELOCITY 3,500 F/S", `ordnance-1944.md:727`, under the
    "105-MM H.E. SHELL, M1" heading, `ordnance-1944.md:726`).

- (b)/(c) Table 51 (CASUALTIES) gives a per-range "lightest effective
    fragment" weight `m(r)` [oz] and velocity `v(r)` [f/s], same layout as
    the 75mm case: two tables (51 CASUALTIES, 52 PERFORATION) are interleaved
    row-by-row in the raw two-column OCR scan (`ordnance-1944.md:729-751`).
    Disambiguated by range grid: Table 51 has 11 rows spanning 20-300 ft,
    Table 52 has 11 rows spanning 20-500 ft — the same identification method
    the sibling 75mm/105mm B(r) scratch scripts already used
    (`experiment/fragmentation-field/_scratch/ordnance-1944-check-105mm.py`
    docstring). That scratch script also documents a known r=100 ft

## Model-computed / model-used values (`arty.shells`, `arty.fragmentation`)

- (a) Gurney V0 for 105mm M1 HE: `arty.fragmentation.gurney_velocity(SHELLS["105mm   M1 HE"])` = **994.2 m/s = 3,261.9 f/s** (Gurney const 2440 m/s for TNT,
    `mass_shell` = mass_total 14.97 − mass_filler 2.18 − mass_deductions 0.75
    = 12.04 kg, C/M = 0.181). This is **6.8% lower** than the source-stated
    3,500 f/s (1,066.8 m/s) — same direction as the 75mm case (model low),
    smaller magnitude (75mm was 15.1% low).
- (b) Minimum lethal fragment mass / energy threshold: same as the 75mm
    check — `min_lethal_mass()`/`ke_at_range()` bisect on a *given* `E_leth`;
    the b-vs-range challenge passes `E_leth=58 ft-lb ≈ 78.6 J` explicitly, and
    the source's own Table 51 rows satisfy 0.5·m·v² ≈ 57.7-58.2 ft-lb at
    every one of the 11 tabulated ranges (see above) — so, as with the 75mm
    shell, the threshold used by the model already matches the source and is
    not a free parameter to investigate further.
- (c) Model velocity-vs-range: same exponential decay law,
    `v(s) = V0 · exp(-λ(m)·s)` with `λ = retardation_coeff(m)`
    (`fragmentation.py:220-227`), fragment-mass-dependent drag deceleration.

**Table-identification correction (found during transcription verification,
not originally in scope):** the existing repo scratch check
`experiment/fragmentation-field/_scratch/ordnance-1944-check-105mm.py`
identifies the CASUALTIES table (Table 51) as the interleaved-row sequence
with range grid 20-300 ft (11 rows), on the heuristic that this matches the
shell's "~300 ft max range." That heuristic is **wrong for the 105mm M1**:
computing 0.5·m·v² for that sequence's own (m, v) pairs gives 248-930 ft-lb —
far above the 58 ft-lb casualty criterion, and *increasing* with range
(physically backwards for a fixed lethality threshold). The *other*
interleaved sequence (range grid 20-500 ft, 11 rows) gives 57.7-58.2 ft-lb at
essentially every range (10 of 11 rows; the 11th, r=100 ft, is the same
single-row column-transposition the scratch script already documents, just
attributed to the wrong table). This is physically sensible the other way
round too: casualties (58 ft-lb) requires much less energy than perforating
1/8-in. mild steel, so the casualty-effective range should extend *further*
(500 ft) than the perforation-effective range (300 ft), not the reverse. So
**Table 51 CASUALTIES is the 20-500 ft sequence, and Table 52 PERFORATION is
the 20-300 ft sequence** — the opposite of the existing scratch script's
labeling. This check reuses the source's own Table 51 (energy-validated,
corrected identification) m(r), v(r) triples below; it does not touch the
`ordnance-1944-check-105mm.py` B(r) comparison script itself (out of scope —
flagged for a follow-up fix, see Implication below).

## Comparison

**(a) V0 — 6.8% low, wrong direction to explain over-prediction, same
pattern as 75mm.** Model Gurney V0 = 994.2 m/s vs source-stated 1,066.8 m/s
(3,500 f/s): model is **6.8% too low**. As with the 75mm case, a too-low V0
makes fragments less energetic at every range (and reduces `N0` via
`mott_params`'s `mu ~ (r_bu/V0)^3`), biasing the model toward
*under*-predicting casualties — the wrong direction to explain an
over-prediction. Confirms the 75mm finding: this is not the driver, and the
model is *not* systematically over-generous with V0 across shells (both
calibers show model V0 running low, 105mm by a smaller margin than 75mm).

**(b) Energy threshold — already matched, ruled out, same as 75mm.** The
source's own Table 51 (corrected identification) satisfies the 58 ft-lb
criterion at 10/11 tabulated ranges to within ~0.5 ft-lb, and the model
challenge script already substitutes this same 78.6 J threshold for
`E_LETH_DEFAULT`. This input is correctly aligned and is not the cause.

**(c) Velocity-vs-range — large, range-growing discrepancy, same pattern and
similar magnitude to 75mm.** Feeding the model's own `retardation_coeff(m)`
the source's per-range lightest-effective-fragment mass `m(r)` and the
source's own V0 (3,500 f/s), the model's predicted `v(s) = V0·exp(-λ(m)·s)`
**overshoots the source's reported v(r) by a growing factor**: ~1.3-1.7× at
r=20-40 ft, rising to **~3.6-4.1× at r=300-500 ft**. Fitting a range-local λ
directly from the source's `(m(r), v(r))` pairs and V0 shows the source's
*implied* retardation coefficient is **~3.1-5.3× larger** than
`retardation_coeff` computes for that same fragment mass — peaking around
r=60-100 ft (~5.2-5.3×) and gently falling to ~3.1× by r=500 ft, the same
non-monotonic-but-order-several shape (not a constant offset) found for the
75mm shell (which peaked ~5.5× at short range, falling to ~3.2× by 400 ft).
Concretely: model `λ(0.010 oz)` ≈ 0.0138 m⁻¹ vs. source-implied ≈ 0.0592 m⁻¹
at r=20 ft (ratio 4.3×).

## Implication for the B(r) over-prediction

The 105mm M1 HE result **reproduces the same pattern found for the 75mm
M48** on all three checked inputs: V0 runs low (wrong direction to explain
over-prediction, ~7% vs 15%), the 58 ft-lb lethal-energy threshold is
already correctly matched, and `retardation_coeff`'s drag deceleration is
several-fold too small compared to the source's own implied velocity decay,
with the gap growing over most of the tabulated range (peaking mid-range
here rather than at the far end, but of the same 3-5× order as 75mm
throughout). This corroborates
\[[project_family_b_overprediction_three_calibers]\] and specifically the
same physics-level hypothesis already logged for 75mm: the under-decelerated
fragments make `min_lethal_mass(s, ...)` return a systematically too-low
threshold mass at longer range, so `mott_N` overcounts still-lethal
fragments — an effect that compounds with range and is now confirmed on a
second, independent caliber with its own fragment count, velocity, and
Gurney parameters. As with 75mm, the leading candidate for the missing
factor is `DragParams`'s `C_D=0.65`/`C_shape=0.90` (combined ≈0.585)
understating the true presented-area/drag of irregular, tumbling steel
fragments; a combined value of order 2-3 would close most of the gap. This
remains a hypothesis to quantify and fix in a follow-up derivation pass on
the drag/retardation law, not confirmed here.

**Separate, orthogonal finding — flag for follow-up, not fixed here:** the
Table 51/52 identity swap found while transcribing the source data (see
"Table-identification correction" above) affects
`experiment/fragmentation-field/_scratch/ordnance-1944-check-105mm.py`'s
`CARD_B` array, which is built from the *perforation* table (mislabeled as
casualties) rather than the true Table 51 CASUALTIES. If the main
`ordnance-1944-b-vs-range.qmd` 105mm comparison sources its card data from
that same mislabeled sequence, the reported 105mm B(r) over-prediction
ratios would need re-deriving against the corrected casualties table before
they can be trusted quantitatively (though the family-wide over-prediction
pattern is independently confirmed on 75mm and 155mm, so the qualitative
conclusion in \[[project_family_b_overprediction_three_calibers]\] is unlikely
to change). This is a data-correction task for whoever next touches the
105mm B(r) challenge, not addressed in this initial-conditions pass.

**Not investigated further here (secondary, smaller effects):** the 6.8% V0
shortfall (wrong-direction fix candidate, smaller than 75mm's 15%); whether
the 105mm's Gurney inputs (`mass_deductions=0.75` kg, `wall_t` from a shared
M60-smoke-shell drawing) are individually accurate — minor next to the
drag-law gap.
